# 4. Enterを待たずにキー入力を受け取る――Rawモード

前章では、JavaScriptでターミナルの好きな位置に文字を描画する関数を作成しました。画面出力を行えるようになったので、次はキーボードを使ってブロックを動かします。

テトリスでは、方向キーを押した瞬間にブロックを移動させる必要があります。しかし、通常のターミナル入力はEnterキーが押されるまでプログラムへ渡されません。この章では入力をRawモードへ切り替え、キーを一つ押すたびに処理を実行できるようにします。

## 4.1 キー入力がプログラムへ届くまで

第3章では、Node.jsが標準出力へ書き込んだ文字列をターミナルが解釈し、画面へ表示する流れを説明しました。キー入力はターミナルからNode.js側へ渡されるため文字出力とは方向が逆になります。ところが、ターミナルからNode.jsへ直接渡されるわけではありません。概念的には、次の経路を通ります。

```text
キーボード
    ↓
ターミナルエミュレーター
    ↓ 文字やエスケープシーケンス
カーネルのラインディシプリン (Enterキーが押されるまで入力をバッファリング)
    ↓ 標準入力 (行単位で受け渡す)
Node.jsプログラム
```

**ターミナルエミュレーター**は、文字を表示する画面であると同時に、押されたキーを文字や制御用のデータへ変換して受け渡すプログラムです。

**ラインディシプリン**は、カーネル（OSの中核部分）の中にある、ターミナルから届いた入力をプログラムへ渡す前に処理する仕組みです。入力を一時的に蓄える、入力した文字を画面へ表示する、`Ctrl+C`を終了シグナルへ変換するといった処理を担当します。

ラインディシプリンが入力をどのように扱うかは、端末の入力モードによって変わります。本記事で扱うのは、**カノニカルモード**と**Rawモード**です。

| 項目 | カノニカルモード | Rawモード |
| --- | --- | --- |
| プログラムへ渡す単位 | Enterまでの一行 | キー入力ごと |
| 入力文字の自動表示 | あり | なし |
| Backspaceなどの基本的な行編集 | ラインディシプリンが処理 | プログラム側で処理 |
| `Ctrl+C` | 通常は終了シグナルになる | 文字コードとして届く |

カノニカルモードでは、ラインディシプリンが入力をEnterキーまで蓄え、確定した一行をプログラムへ渡します。Rawモードでは行単位の処理だけでなく、入力文字の自動表示や特殊キーの変換なども無効になり、入力がプログラムへほぼそのまま渡されます。

つまり、Rawモードは単に「Enterキーを待たなくする設定」ではありません。ターミナル側の入力処理をスルーしてプログラム側で受け取り、入力キーに応じて処理をきめ細かく制御するための設定です。

## 4.2 普段のターミナル入力は行単位

対話型のBashでコマンドを入力するときは、Backspaceキーで文字を消したり、左右の矢印キーで入力位置を移動したりできます。これらは主に、Bashが利用する行編集ライブラリのReadlineが処理しています。Readlineは入力中の文字列とカーソル位置を管理し、Enterキーが押されると、編集を終えた一行をBashへ渡します。

一方、Readlineのような行編集機能を持たないNode.jsプログラムの標準入力は、通常カノニカルモードです。そのため、左右の矢印キーによる編集機能はなく、入力はEnterキーまでラインディシプリンに蓄えられます。

たとえば、次のプログラムを実行して文字を入力しても、`data`イベントはすぐには発生しません。Enterキーを押した時点で、入力した一行がまとめて `data` へ渡されます。

```js
process.stdin.setEncoding('utf8');

process.stdin.on('data', (data) => {
  console.log(`受け取った値: ${JSON.stringify(data)}`);
});
```

```text
abc                    ← 入力しただけではイベントは発生しない
受け取った値: "abc\n"   ← Enterキーを押すと一行分が届く
```

行単位の入力はコマンドを扱う場合には便利ですが、ゲームではキー入力単位での処理が必要です。そこで、Node.jsからターミナルの入力をRawモードへ切り替えます。

Node.jsでは、標準入力を表す `process.stdin` に対して `setRawMode(true)` を呼び出します。

```js
if (!process.stdin.isTTY) {
  throw new Error('対話型ターミナル上で実行してください');
}

process.stdin.setRawMode(true);
process.stdin.resume();
process.stdin.setEncoding('utf8');
```

それぞれの処理には、次の役割があります。

| 処理 | 役割 |
| --- | --- |
| `process.stdin.isTTY` | 標準入力が対話型ターミナルに接続されているか確認する |
| `setRawMode(true)` | 入力をRawモードへ切り替える |
| `resume()` | 標準入力からの読み取りを開始する |
| `setEncoding('utf8')` | 入力を`Buffer`ではなく文字列として受け取る |

`setRawMode()` は、標準入力がターミナルに接続されている場合に使用できます。そのため、ファイルから入力をリダイレクトするのではなく、対話型ターミナル上で実行している必要があります。

設定後に `data` イベントを登録すると、Enterキーを押さなくてもキー入力を受け取ることができるようになります。

```js
process.stdin.on('data', (key) => {
  process.stdout.write(`入力: ${JSON.stringify(key)}\r\n`);

  if (key === '\u0003') { // Ctrl+C
    process.stdin.setRawMode(false);
    process.stdin.pause();
  }
});
```

`JSON.stringify()`を使って表示すると、目に見えない制御文字も `"\u001b[D"` のような表記で確認できます。

## 4.3 矢印キーもエスケープシーケンス

文字キーを押すと、`a` や `x` のような文字列を受け取れます。一方、矢印キーには表示可能な一文字が割り当てられていません。代わりに、`ESC`から始まる複数文字のエスケープシーケンスが送られます。

今回の実行環境では、矢印キーを押すと次の文字列を受け取ります。

| キー | 受け取る値 | 構成 |
| --- | --- | --- |
| ↑ | `\u001b[A` | `ESC`、`[`、`A` |
| ↓ | `\u001b[B` | `ESC`、`[`、`B` |
| → | `\u001b[C` | `ESC`、`[`、`C` |
| ← | `\u001b[D` | `ESC`、`[`、`D` |

JavaScriptの `\u001b` と、第3章で使った `\x1b` は、どちらも文字コード `1b` の `ESC`を表します。記述方法は違いますが、文字列としての値は同じです。

出力では `ESC [ 3 ; 5 H` のようなシーケンスをターミナルへ送り、カーソルを移動しました。入力では反対に、ターミナルからNode.jsプログラムへ `ESC [ D` などのシーケンスが届きます。同じ形式の制御文字列が、ターミナルとの双方向のやり取りに使われています。

### 押された矢印キーを画面へ描く

まずは、矢印キーを押すたびに座標を更新し、押した方向の矢印を表示してみます。`draw()` は第3章で作成した、任意の座標へ文字を表示する関数です。途中で呼び出している `restoreTerminal()` は、4.4節で作成します。

```js
let x = 10;
let y = 5;

process.stdin.setRawMode(true);
process.stdin.resume();
process.stdin.setEncoding('utf8');

process.stdin.on('data', (key) => {
  let symbol = '';

  if (key === '\u0003') { // Ctrl+C
    restoreTerminal();
    return;
  }

  switch (key) {
    case '\u001b[D': // ←
      x = Math.max(0, x - 1);
      symbol = '←';
      break;
    case '\u001b[C': // →
      x += 1;
      symbol = '→';
      break;
    case '\u001b[B': // ↓
      y += 1;
      symbol = '↓';
      break;
    case '\u001b[A': // ↑
      y = Math.max(0, y - 1);
      symbol = '↑';
      break;
  }

  if (symbol !== '') {
    draw(x, y, symbol);
  }
});
```

押したキーに応じて `x` または `y` が変化し、新しい位置へ矢印が描かれます。これで、キー入力を座標の更新へ変換できました。

この例では入力を確認するために上下左右へ移動していますが、完成版のテトリスでは次のように操作を割り当てます。

| キー | ゲーム内の操作 |
| --- | --- |
| ← | ブロックを左へ1セル移動する |
| → | ブロックを右へ1セル移動する |
| ↓ | ブロックを下へ1セル移動する |
| ↑ または `x` | ブロックを時計回りに回転する |
| `z` | ブロックを反時計回りに回転する |
| `Ctrl+C` | ゲームを終了する |

入力の判定は、`switch`文にまとめると操作との対応が分かりやすくなります。

```js
function handleKeyPress(key) {
  switch (key) {
    case '\u001b[D': // ←
      moveLeft();
      break;
    case '\u001b[C': // →
      moveRight();
      break;
    case '\u001b[B': // ↓
      moveDown();
      break;
    case '\u001b[A': // ↑
    case 'x':
      rotateRight();
      break;
    case 'z':
      rotateLeft();
      break;
  }
}

process.stdin.on('data', handleKeyPress);
```

ここでは役割を分かりやすくするため、移動や回転を関数名だけで示しています。実際には、移動先や回転後のブロックが壁と重ならないかを確認してから状態を更新します。この処理は第5章で実装します。

なお、`data`イベントの値は、必ず一回のイベントにつき一つのキーだけになるとは限りません。キーを非常に速く入力した場合や文字列を貼り付けた場合は、複数の入力が一度に届くことがあります。今回の最小構成では矢印キーの文字列と完全一致するかを判定しますが、より厳密な入力処理に発展させる場合は、届いた文字列を順番に解析する必要があります。

## 4.4 終了時にターミナルを元へ戻す

ゲーム中は、通常のコマンド入力とは異なる状態へターミナルを変更します。

- 標準入力をRawモードにする
- ゲーム画面の邪魔にならないようにカーソルを非表示にする

カーソルの表示と非表示も、エスケープシーケンスで切り替えられます。

| 操作 | エスケープシーケンス |
| --- | --- |
| カーソルを非表示にする | `\x1b[?25l` |
| カーソルを表示する | `\x1b[?25h` |

ゲームの開始時には、Rawモードへの切り替えとカーソルの非表示をまとめて行います。

```js
function setupTerminal() {
  if (!process.stdin.isTTY) {
    throw new Error('対話型ターミナル上で実行してください');
  }

  process.stdout.write('\x1b[?25l');
  process.stdin.setRawMode(true);
  process.stdin.resume();
  process.stdin.setEncoding('utf8');
}
```

終了時には、行った変更を逆の順番で元へ戻します。

```js
function restoreTerminal() {
  if (process.stdin.isTTY && process.stdin.isRaw) {
    process.stdin.setRawMode(false);
  }

  process.stdin.pause();
  process.stdout.write('\x1b[?25h');
}
```

Rawモードでは、`Ctrl+C`を押しても自動的にはプログラムが終了しません。代わりに、`Ctrl+C`を表す制御文字 `\u0003` が `data`イベントへ届きます。そのため、入力処理の中で復元処理を呼び出してから終了します。

```js
function handleKeyPress(key) {
  if (key === '\u0003') {
    restoreTerminal();
    return;
  }

  // 移動や回転の処理
}
```

`process.exit()`だけを呼び出すと、次に表示されるシェルでも入力文字が見えなかったり、カーソルが消えたままになったりすることがあります。終了前にRawモードを解除し、カーソルを再表示することを忘れずに行ってください。

通常の終了処理でも復元が必要なため、`exit`イベントにも登録しておきます。`restoreTerminal()`を複数回呼んでも問題が起きないように、`process.stdin.isRaw`で処理済みチェックを行います。

```js
process.on('exit', restoreTerminal);

setupTerminal();
process.stdin.on('data', handleKeyPress);
```

ゲームオーバーの場合も、タイマーを停止した後に `restoreTerminal()` を呼び出します。

```js
if (gameOver) {
  clearInterval(timer);
  restoreTerminal();
}
```

開発中にプログラムがエラーで終了し、ターミナルの表示や入力が元に戻らなかった場合は、Git Bashで次のコマンドを実行すると復旧できます。入力した文字が画面に見えなくても、そのままコマンドを入力してEnterキーを押してください。

```bash
stty sane
printf '\033[?25h'
```

これで、Enterキーを待たずにキー入力を受け取り、終了時にはターミナルを元の状態へ戻せるようになりました。次章では、盤面とテトリミノを二次元配列で表し、移動、回転、衝突判定、行消去を実装します。
